# AutoKolpak AI v2

## Документация проекта

**Проект:** AutoKolpak AI v2  
**Назначение:** распознавание автомобильных колпаков по фотографии, параметрическое построение 3D-моделей и генерация моделей крепёжных деталей  
**Основной режим:** локальный API и веб-интерфейс  
**Версия документа:** 1.0  
**Дата:** 26 ноября 2026 года

---

## 1. Введение

AutoKolpak AI v2 — локальное веб-приложение для реконструкции автомобильных колпаков и создания параметрических моделей метизов. Пользователь может загрузить фотографию колпака, указать измеренные размеры, получить анализ формы и построить модель через Blender. Для крепёжных деталей предусмотрен каталог параметрических изделий: болты, винты, гайки, шайбы, втулки, анкеры, заклёпки, штифты, шплинты и крепёжные уголки.

Система состоит из FastAPI API, веб-интерфейса на HTML/JavaScript, AI-сервиса анализа изображений и Blender-генератора. Результаты сохраняются в формате GLB, а просмотр выполняется непосредственно в браузере.

## 2. Актуальность и проблема

Восстановление внешнего вида детали по фотографии обычно требует ручного моделирования. Фотография описывает форму, но не содержит надёжного абсолютного масштаба, а отдельные элементы изделия могут быть скрыты или находиться вне ракурса.

Проект решает эту задачу в два этапа:

1. AI определяет видимую форму и относительные особенности детали.
2. Пользователь вводит измеренные размеры, после чего Blender создаёт параметрическую 3D-модель.

Такой подход не выдаёт визуальную оценку за точное измерение и позволяет изменять параметры без повторного моделирования вручную.

## 3. Цель и задачи

### Цель

Создать локальную инженерную среду, которая позволяет анализировать фотографию автомобильного колпака, редактировать параметры, просматривать результат в 3D и строить параметрические модели метизов.

### Задачи

- принимать изображения через API;
- проверять размер, формат и разрешение изображения;
- передавать фотографию AI-сервису;
- сохранять пользовательские размеры и относительные пропорции;
- строить модели через Blender 4.2;
- экспортировать валидные GLB-файлы;
- отображать GLB-модели в браузере;
- поддерживать каталог метизов и втулок;
- нормализовать связанные размеры деталей;
- сохранять проекты в SQLite;
- предоставлять локальный запуск без отдельного frontend-сервера.

## 6. Установка на новом компьютере

Требуются:

- Python 3.12;
- Blender 4.2;
- API-ключ AI-провайдера для анализа фотографий;
- доступ к локальным файлам проекта.

Создание окружения API-режима:

```powershell
cd C:\путь\к\AutoKolpakAI_Training_v2
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements-web.txt
```

Полный `requirements.txt` нужен для работы обучающей части и содержит PyTorch, torchvision и дополнительные ML-зависимости. Для обычной работы сайта достаточно `requirements-web.txt`.

## 7. Настройка `.env`

Создайте в корне проекта файл `.env` на основе `.env.example`:

```env
HOST=127.0.0.1
PORT=8000

BLENDER_EXECUTABLE=C:\Program Files\Blender Foundation\Blender 4.2\blender.exe

ANTHROPIC_BASE_URL=https://api.anthropic.com
ANTHROPIC_AUTH_TOKEN=ваш_ключ
ANTHROPIC_MODEL=claude-sonnet-5
```

Для другого провайдера можно использовать:

```env
OPENAI_API_KEY=ваш_ключ
OPENAI_BASE_URL=https://api.openai.com/v1
OPENAI_MODEL=gpt-4.1-mini
```

Ключи нельзя добавлять в Git. В документацию и отчёты следует помещать только названия переменных, без их значений.

Основные переменные:

| Переменная | Назначение |
|---|---|
| `BLENDER_EXECUTABLE` | абсолютный путь к `blender.exe` |
| `HOST` | адрес API-сервера |
| `PORT` | порт API-сервера |
| `METIZ_DATABASE_PATH` | путь к SQLite-базе проектов |
| `METIZ_GENERATED_DIR` | каталог созданных моделей |
| `METIZ_REQUEST_TIMEOUT` | тайм-аут запуска Blender |
| `METIZ_MAX_UPLOAD_MB` | максимальный размер изображения |
| `ANTHROPIC_AUTH_TOKEN` | ключ Claude |
| `ANTHROPIC_BASE_URL` | адрес Anthropic-совместимого API |

## 10. Работа с колпаками

### AI-анализ фотографии

Пользователь:

1. открывает вкладку AI-сканера;
2. загружает фотографию;
3. указывает наружный диаметр и другие измеренные размеры;
4. запускает анализ;
5. проверяет распознанное семейство, количество спиц, центр и отделку;
6. при необходимости изменяет параметры;
7. запускает построение модели.

Фотография определяет форму и относительные признаки. Абсолютные размеры должны быть введены пользователем, поскольку по одной фотографии без масштаба нельзя надёжно определить физический размер.

### Параметрическая геометрия

Генератор колпаков использует:

- наружный диаметр;
- глубину обода;
- толщину лицевой части;
- выпуклость;
- диаметр центрального отверстия;
- семейство спиц;
- число спиц;
- ширину и изгиб спиц;
- тип центра;
- отделку;
- болтовую окружность и крепления.

Лицевая основа, ступица и внешняя опора спиц создаются с перекрытием, чтобы элементы модели не выглядели как отдельные объекты, летающие в воздухе.

## 11. Работа с метизами

Раздел «Другие изделия» получает каталог через:

```text
GET /api/metiz/catalog
```

Поддерживаются категории:

- болты и винты;
- гайки;
- шайбы;
- заклёпки;
- анкеры;
- штифты;
- шплинты;
- уголки;
- втулки и дистанционные элементы.

Для резьбовых деталей доступны метрические стандарты M3–M20. При выборе стандарта диаметр и рекомендуемый шаг резьбы согласуются автоматически.

Генератор учитывает связанные размеры: внутренний диаметр втулки, толщину стенки, длину резьбы, высоту буртика, размер головки, число отверстий, прорезей и зубьев.

## 12. API-методы

### Основные методы

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/api/health` | состояние AI-сервиса |
| `GET` | `/api/model-info` | информация о режиме анализа |
| `POST` | `/api/predict` | анализ фотографии колпака |
| `POST` | `/api/hubcaps/generate` | построение колпака по параметрам |
| `POST` | `/api/models/generate` | построение любого изделия |
| `GET` | `/api/metiz/catalog` | каталог метизов и материалов |
| `GET` | `/api/metiz/defaults/{part_type}` | значения по умолчанию |
| `POST` | `/api/metiz/models/generate` | построение модели метиза |
| `POST` | `/api/metiz/ai/analyze` | анализ фотографий метиза |
| `GET` | `/api/metiz/projects` | список проектов |
| `POST` | `/api/metiz/projects` | сохранить проект |
| `PUT` | `/api/metiz/projects/{id}` | обновить проект |
| `DELETE` | `/api/metiz/projects/{id}` | удалить проект |

### Пример запроса метиза

```json
{
  "category": "fastener",
  "part_type": "hex_bolt",
  "material": "steel",
  "params": {
    "thread_standard": "M10",
    "length": 50,
    "thread_length": 32
  }
}
```

### Пример запроса уголка

```json
{
  "category": "bracket",
  "part_type": "angle_bracket",
  "material": "steel",
  "params": {
    "length": 50,
    "width": 40,
    "height": 40,
    "wall_thickness": 4,
    "holes_count": 8,
    "hole_diameter": 6
  }
}
```

`holes_count` задаёт общее количество отверстий на двух полках уголка. При слишком большом значении генератор ограничивает размещение, чтобы отверстия не пересекались.

## 13. Blender и экспорт

Сервис запускает Blender отдельным процессом:

```text
blender.exe -b --python blender/runtime_generate.py -- --input request.json --output model.glb
```

Перед экспортом:

- Curve-объекты резьбы преобразуются в Mesh;
- модификаторы применяются;
- масштаб объектов применяется;
- проверяются вершины и полигоны;
- Mesh-объекты объединяются;
- создаётся GLB версии 2;
- файл проверяется по заголовку `glTF`.

Созданные модели доступны через:

```text
/generated/<filename>.glb
```

## 14. Тестирование и проверка

Компиляция Python:

```powershell
python -m compileall -q app blender scripts src
```

Проверка тестов:

```powershell
python -m pytest -q
```

Если `pytest` не установлен:

```powershell
pip install -r requirements.txt
```

Smoke-проверка Blender должна проверять как минимум:

- болт с внешней резьбой;
- гайку с внутренней резьбой;
- втулку;
- уголок с разным количеством отверстий;
- анкер;
- корончатую гайку;
- пружинную и стопорную шайбы.

Предупреждение Blender `TBBmalloc` на Windows не означает автоматически ошибку генерации. Ориентироваться нужно на код завершения процесса, наличие GLB и его заголовок.

## 15. Известные ограничения

- Фотография без эталонного размера не даёт точный масштаб.
- Геометрия является параметрическим инженерным эскизом и требует проверки перед производством.
- Номинальная модель резьбы предназначена для визуализации и параметрического экспорта, а не для сертифицированного производства без дополнительной CAD-проверки.
- Blender должен быть установлен отдельно и доступен по `BLENDER_EXECUTABLE`.
- AI-анализ требует доступного и настроенного внешнего API.
- `pytest` не запускает полноценное обучение и не заменяет проверку реальной геометрии в Blender.
- STL/OBJ импорт зависит от наличия соответствующих загрузчиков в frontend; GLB/GLTF поддерживаются через локальный GLTFLoader.

## 16. Перенос проекта на другой компьютер

1. Скопировать проект без старого `.venv`.
2. Установить Python 3.12 и Blender 4.2.
3. Создать новое виртуальное окружение.
4. Установить `requirements-web.txt`.
5. Создать `.env`.
6. Указать новый путь к Blender.
7. Указать ключ AI-провайдера.
8. Запустить `start.bat` или Uvicorn.

Старое виртуальное окружение и абсолютные пути переносить нельзя. Папки `runs` и датасет не нужны для API-режима, если обучение собственной нейронной сети не выполняется.

## 17. Выводы и перспективы

AutoKolpak AI v2 объединяет AI-анализ фотографии, параметрическое моделирование и локальный 3D-просмотр в одном приложении. Основное преимущество проекта — разделение визуального распознавания и физических размеров: форма определяется по изображению, а масштаб подтверждается пользователем.

Дальнейшее развитие проекта может включать:

- полноценный ISO-профиль внешней и внутренней резьбы;
- STL и OBJ загрузку в браузере;
- проверку manifold-геометрии и самопересечений;
- расширение каталога стандартных деталей;
- режим сечения втулок и гаек;
- автоматическое отображение габаритных размеров;
- отдельные быстрый и точный режимы генерации;
- интеграцию с реальными измерениями и производственными допусками.
