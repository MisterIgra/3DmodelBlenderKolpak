# AutoKolpak AI v2 — генерация данных, обучение, проверка и веб-интерфейс

Это **новая совместимая версия** обучающего проекта и веб-адаптера для Blender Generator v4. Старые веса `runs/best.pt` использовать нельзя: в них другой набор классов и другая размерность выходных слоёв. Новый `best.pt` нужно получить после генерации/проверки датасета и обучения этим пакетом.

## Главные исправления

- Одна схема меток для Blender Generator v4 и ИИ: семейства `classic`, `v_shaped`, `split`, `y_shaped`, `mesh`; видимые концы спиц — 5–24; тип центра; тип отделки.
- Автоматическая проверка изображений, меток, диапазонов размеров, согласованности ракурсов одной модели и повторов геометрии до запуска обучения.
- Разделение train/validation/test **по `model_id`**, а не по отдельным изображениям. Все ракурсы одной модели остаются в одном split.
- Изображения приводятся к квадрату без растягивания диска; препроцессинг общий для train/inference.
- Предобученный ResNet-18, отдельные головы для задач, разные learning rate для backbone и голов, AdamW, cosine schedule, mixed precision на CUDA, clipping градиентов и early stopping.
- Размерные регрессии обучаются на **относительных пропорциях**, а не на абсолютных миллиметрах. Значения нормализуются в `[-1, 1]`, чтобы регрессия в миллиметрах не задавливала/не искажала классификационные задачи. Диаметр центрального отверстия не обучается на ракурсах, где отверстие закрыто декоративной крышкой.
- `best.pt` содержит только веса и метаданные; `last.pt` дополнительно содержит состояние оптимизатора для продолжения v2-обучения. В чекпойнте хранится test split.
- Отчёт качества включает accuracy, macro-F1, confusion matrix и MAE пропорций на отложенных моделях.
- Веб-API использует ту же схему и не выдаёт фиктивные миллиметры без известного наружного диаметра.

## Важно до старта

1. **Сгенерируйте датасет заново** с приложенным `blender/generate_dataset.py` из этого архива. Старые датасеты с классами `Classic/Sport/Turbine/...` не подходят: автоматическая проверка намеренно остановит обучение.
2. Для разумного первого набора используйте около **10 000 уникальных моделей и 2 ракурса** каждой: примерно 20 000 PNG. Один ракурс преимущественно фронтальный, второй наклонный. Уберите STL/OBJ экспорт при генерации датасета — он замедляет работу и не нужен для обучения по фотографиям.
3. Никакие настройки не могут гарантировать идеальную точность по настоящим фото, если модель обучалась только на синтетических рендерах. После синтетического обучения нужны реальные фото с корректными метками, отдельно от train, иначе реальная точность неизвестна.
4. По одиночной некалиброванной фотографии невозможно определить абсолютный физический размер в миллиметрах: масштаб зависит от расстояния и камеры. Для перевода отношений в мм в форме сайта введите **измеренный наружный диаметр**. Даже тогда значения других размеров — оценки по визуальным пропорциям, а не замена инструментального измерения.

## 1. Подготовить Python на Windows

Рекомендуется Python 3.12 и установленный Blender 4.2 LTS. Откройте PowerShell в корне распакованного архива:

```powershell
py -3.12 -m venv .venv_gpu
.\.venv_gpu\Scripts\Activate.ps1
python -m pip install --upgrade pip
```

Сначала установите PyTorch и torchvision под вашу версию CUDA/драйвера через официальный селектор: <https://pytorch.org/get-started/locally/>. Затем:

```powershell
pip install -r requirements.txt
pip install -e . --no-deps
python scripts/check_environment.py
```

Если `CUDA available: False`, обучение пойдёт на CPU и будет значительно медленнее. Не меняйте рабочее CUDA-окружение, пока `check_environment.py` не подтвердит правильную видеокарту.

## 2. Создать чистый датасет v4

Поменяйте путь к Blender.exe на свой, если установлен не в `C:\Program Files\Blender Foundation\Blender 4.2\`:

```powershell
& "C:\Program Files\Blender Foundation\Blender 4.2\blender.exe" -b --python .\blender\generate_dataset.py -- --output "C:\Users\roman\Documents\blender-dataset\AutoKolpak_generated_v4" --count 10000 --renders-per-model 2 --resolution 512 --no-export-models
```

У генератора не задан фиксированный seed по умолчанию: модели будут разными при каждом новом запуске. Если нужно воспроизводимое создание данных, добавьте `--seed 42`. Не запускайте повторно в ту же папку без `--resume`; для чистого обучения используйте новую папку.

## 3. Проверить сам генератор перед Blender (быстрый preflight)

Эта проверка не требует установленного Blender и не рендерит геометрию; она проверяет 10 000 сгенерированных наборов параметров, все классы спиц, физические диапазоны и уникальность сигнатур:

```powershell
python scripts/check_generator_schema.py --count 10000
```

## 4. Проверить датасет до обучения

```powershell
python scripts/validate_dataset.py --data "C:\Users\roman\Documents\blender-dataset\AutoKolpak_generated_v4" --report .\runs\dataset_report.json
```

Если отчёт `ok: false`, **не начинайте обучение**. Сначала исправьте ошибки в аннотациях. В отчёте указаны проблемные строки, отсутствующие/повреждённые изображения, неверные labels, выход за диапазоны параметров и конфликтующие метки ракурсов. Предупреждения о редких классах нужно разобрать. Повторные геометрические сигнатуры и несовместимая версия генератора блокируют обучение.

## 5. Обучить одну итоговую модель

```powershell
python scripts/train.py --config .\configs\train.yaml --data "C:\Users\roman\Documents\blender-dataset\AutoKolpak_generated_v4"
```

Стандартно: до 45 эпох, ранняя остановка после 8 эпох без улучшения. Обучение может завершиться раньше. Лучший чекпойнт — `runs\best.pt`; последний — `runs\last.pt`; отчёт разделения — `runs\split_report.json`; историю метрик — `runs\history.json`. Прогресс печатается JSON-строкой на каждую эпоху.

Не прерывайте обучение и не удаляйте `runs`. Если продолжить нужно после остановки, укажите **v2 `last.pt`** в `configs/train.yaml`:

```yaml
resume: ./runs/last.pt
```

Старый чекпойнт v1 нельзя возобновить, так как его классификационные классы и выходы несовместимы.

## 6. Оценить итог на test split

```powershell
python scripts/evaluate.py --data "C:\Users\roman\Documents\blender-dataset\AutoKolpak_generated_v4" --checkpoint .\runs\best.pt --output .\runs\evaluation.json
```

Оценка использует сохранённые в checkpoint `model_id` тестовой выборки. **Не меняйте test выборку и не используйте изображения из неё для подбора настроек.** Перед демонстрацией загрузите несколько реальных фото, которых не было в обучении, и отдельно сохраните их прогнозы/ошибки. Accuracy на Blender-рендерах не равна accuracy на реальных фотографиях.

## 7. Предсказать по одной фотографии

Без известного масштаба:

```powershell
python scripts/predict.py --image "C:\path\to\wheel.jpg" --checkpoint .\runs\best.pt
```

С измеренным наружным диаметром 430 мм:

```powershell
python scripts/predict.py --image "C:\path\to\wheel.jpg" --checkpoint .\runs\best.pt --reference-diameter-mm 430
```

Без reference diameter значения `*_mm` останутся `null`, а модель вернёт классификацию и относительные пропорции. Это сделано намеренно, чтобы не выдавать догадки за измерения.

## 8. Запустить сайт/API

В той же среде, где установлен PyTorch:

```powershell
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Откройте `http://127.0.0.1:8000`. На вкладке AI-сканера можно указать измеренный диаметр. API: `/api/health`, `/api/model-info`, `/api/predict`. Сайт автоматически берёт `runs/best.pt` рядом с проектом. Для другого пути задайте `AUTOKOLPAK_WEIGHTS`.

## 9. Диагностика и проверка кода

```powershell
python -m pytest -q
```

Эти тесты проверяют схему labels, нормализацию, групповой split, обработку неквадратных изображений, выходы модели и конечность loss. Они не заменяют полноценную оценку качества на ваших 10 000 моделях/фотографиях и не запускают Blender.

## Ограничения по физическим параметрам

- Тип семейства, отделку, центральную часть и количество видимых концов спиц можно оценивать по изображению.
- Точное физическое значение диаметра без эталона/калибровки не определяется однозначно.
- Диаметр центрального отверстия под декоративной крышкой не выдаётся как измеримый признак. Глубина, толщина и скрытые крепления с фронтального фото часто не наблюдаемы; нужен боковой ракурс и реальные измерения.
- STL/GLB из этой демонстрационной геометрии — параметрический эскиз. Перед изготовлением проверьте CAD-геометрию, посадку, прочность, допуски и крепления.

## Режим работы через API (актуально)

Веб-интерфейс больше не использует локальную нейросеть (`runs/best.pt`, PyTorch не нужен). Распознавание фото выполняет Claude через API. По распознанным пропорциям интерфейс строит параметрическую 3D-модель колпака; STL экспортируется в миллиметрах после ввода измеренного наружного диаметра. GLB/STL — концептуальная геометрия для проверки, не производственная CAD-модель.
Настройки — в файле `.env` в корне проекта (`ANTHROPIC_BASE_URL`, `ANTHROPIC_AUTH_TOKEN`, `AUTOKOLPAK_MODEL`). Запуск — `start.bat`.
